nodoka のどか · calm, peaceful weather

Your computer stays responsive while dev servers, builds, installs and coding agents run. Any stack, macOS and Linux, no new commands, nothing turned off.

How it works

You or an agent run

npm ci, bin/rails server, cargo build, pytest, go run… exactly as today.

→

1 · Fewer workers, leaner memory

Each tool is told about half your cores, and only 2 while memory is short. Node and Bun use their leaner memory settings.

→

2 · Tiny helper

Builds take turns. Idle servers sleep and wake on the next request or saved file. Pauses the newest build when memory is critical. Never pauses a test run.

Safety

Never kills

Only pauses, resumes and lowers priority. Your processes only, no root, no network.

Never breaks your work

Never pauses what a shell waits on, or a test run (it would fail its timeouts). Hot reload keeps working. One line in the terminal when a job has to wait.

Crash-safe and reversible

Writes down what it pauses first; nodoka off resumes all; uninstall removes every line it added.
